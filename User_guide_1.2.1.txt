SECTION STUDIO 1.2.1 — НАДЁЖНОСТЬ И ВОССТАНОВЛЕНИЕ
1 ноября 2026

Эта версия выполняет этап 1.2.1. Редактор, сопряжение с Wing, проверки сетки,
карта зазоров и ограниченный ремонт 1.2 сохранены. Интеграция вычислителей
RepairMach, запуск потока VSPAERO/MachLine и расчёт Cp здесь не добавлялись.
Ниже — изменения 1.2.1; остальные рабочие операции описаны в User_guide_1.2.txt.
При противоречии приоритет у этой инструкции и README.txt.

1. ЗАПУСК И ДИАГНОСТИКА

Полностью распакуй ZIP. Не запускай BAT из временного просмотра архива.
Нужны Python 3.10+ и полный OpenVSP 3.51.x. Сторонние Python-пакеты не нужны.
Start_Section_Studio.bat проверяет наличие файлов и подходящего Python,
затем запускает studio_bootstrap.py. Он сохраняет журнал launch.log и полный
текст неожиданной ошибки. BAT оставляет окно открытым и возвращает код ошибки.

Порядок поиска Python: явно заданный SECTION_STUDIO_PYTHON, переносимый
runtime/python/python.exe рядом с приложением или на двух уровнях выше,
Windows launcher py -3, затем python из PATH. Если нужен конкретный Python,
задай SECTION_STUDIO_PYTHON полным путём к python.exe. Указание неверного
явного пути показывает ошибку. Переносимый Python в сам архив не включён.

OpenVSP ищется по сохранённому пути, OPENVSP_ROOT, PATH, соседним папкам
engines/OpenVSP и обычным местам установки. Всегда можно выбрать путь вручную.
Диалог выбора необязателен: если tkinter отсутствует, вставь путь в поле.
Используй vspscript.exe из полной папки OpenVSP с DLL. Обычный vsp.exe
не подходит для штатных фоновых операций. Ошибки отсутствующей DLL,
неверной разрядности и инициализации теперь поясняются по коду завершения.

Check_Setup.bat проверяет Python, наличие модулей, локальный HTTP, запись
и чтение recovery-копии, блокировку второго экземпляра и повторное открытие
работающего сервера, запуск OpenVSP и создание тестового VSP3.
Он не меняет пользовательские модели и не записывает тестовый проект
в историю восстановления. Путь к Setup_check.json печатается в окне.

По умолчанию настройки, Recovery и журналы находятся в:
Windows: %LOCALAPPDATA%\SectionStudio
Linux: ~/.config/SectionStudio
При --config используется папка указанного файла. Если папка журнала недоступна,
загрузчик печатает путь временного журнала; это не делает недоступную папку
настроек или восстановления пригодной для записи.

Чтение/запись native-файлов явно использует UTF-8 независимо от кодировки
Windows. Busy-блокировка снимается до передачи завершённого HTTP-ответа:
следующий запрос не получает ложное «OpenVSP занят» после готового результата.

Журнал launch.log ограничен примерно 2 МБ и двумя резервными файлами.
Сохранённые настройки записываются через временный файл и замену; предыдущий
корректный вариант остаётся settings.json.bak. При повреждении основного
JSON читается резервный и показывается сообщение. Неверный путь к вычислителю
не заменяет рабочую настройку.

Обычный повторный запуск с тем же --config открывает уже работающий экземпляр.
При аварийном завершении блокировка освобождается операционной системой;
наличие старого instance.lock само по себе не запрещает новый запуск.
Диагностика --self-test выполняется отдельно. Разные файлы --config позволяют
изолированные профили с отдельными настройками и копиями восстановления.

Linux: python3 studio_bootstrap.py --vspscript /путь/vspscript
Диагностика: та же команда с --self-test.
Прямой запуск section_studio_server.py также сохранён, но без загрузочного
журнала bootstrap. Все штатные Windows BAT используют загрузчик.

2. АВТОВОССТАНОВЛЕНИЕ

При локальном запуске панель «Автовосстановление проекта» доступна без
подключённого OpenVSP: сохранение проекта не требует запуска вычислителя.
После открытия или допустимого изменения проекта копия сохраняется на диск
через 1,5 с без новых правок. При непрерывном редактировании интервал
ограничен примерно 10 с. «Сохранить копию сейчас» запускает запись вручную.

Копия содержит весь проект: исходный XML, единицы, корпуса и их повороты,
выбранную пару, крыло, защиты, категории и журнал правок. Это отдельный файл
в Recovery; исходный VSP3 и вручную сохранённый JSON не перезаписываются.
Проверены проекты размером около 4,4 МБ. Browser localStorage не используется:
копии доступны после перезапуска программы и смены localhost-порта.

Хранятся три последние проверенные копии; одинаковый проект не создаёт новую
генерацию. Это краткая история восстановления, а не архив всех самолётов.
Изменения сохраняются через временный файл и атомарную замену. Контрольная
сумма проверяет содержимое снимка. Повреждённый файл исключается из выбора,
исправная предыдущая копия остаётся доступной. Для диагностики может оставаться
до трёх повреждённых снимков. Их нельзя считать рабочими проектами.

После сбоя:
1) Запусти Start_Section_Studio.bat.
2) Раскрой «Автовосстановление проекта».
3) Выбери имя и время исправной копии.
4) Нажми «Восстановить». Текущее состояние остаётся в истории Undo.
5) Выполни нативные проверки заново, затем сохрани JSON и VSP3.

Результаты текущих фоновых задач и разрешения Apply не восстанавливаются
как готовый расчёт. Система координат и сохранённые торцы проверяются
по значениям полей; форматирование и порядок ключей JSON больше не вызывают
ложный отказ. Изменение самих координат исходной системы по-прежнему запрещено.

Предел автокопии — 60 МБ. Предел обычного импорта JSON остаётся 80 МБ.
При переполнении диска, запрете записи или разрыве соединения в заголовке
панели показывается ошибка. Сохрани JSON вручную и устрани причину.
В отдельном HTML без локального сервера дисковое автовосстановление недоступно.
Последние изменения до срабатывания записи при жёстком сбое могут потеряться.
Для длительного хранения используй обычное сохранение JSON и резервные копии.

3. ВХОДЫ И СОПЛА

Исправлено сопоставление исходных станций с фактической поверхностью, когда
OpenVSP обрезает тракт до губ или расчётных плоскостей. Ранее скрытые обрезкой
станции ошибочно требовались на поверхности и давали неполный результат MQ-20.
Теперь учитывается активный диапазон native-параметров до добавления крышек,
после чего его сопоставление проверяется плоскостями видимых станций.

Проверены обычные To Lip/To Face, дробные положения U и общий поворот корпуса
с ненулевой Origin. Исходные режимы двигателя, индексы, сечения и геометрия
для распознавания не меняются. У контрольного MQ-20 распознаны все 4296 граней,
включая 96 граней расчётных торцов; нативная проверка плавности завершена.
Обратные Free-ветви CH1 также продолжают распознаваться.

Сравнение после вставки станций использует только общие ID, видимые в обоих
вариантах с учётом обрезки. Скрытые исходные станции не подменяют соответствие
плоских торцов. Для автодоводки скрытые станции и границы обрезки защищены.

Произвольные дополнительные отрицательные поверхности, удлинение тракта
и его циклический поворот остаются ограниченными режимами: программа сохраняет
исходный файл и явно показывает неполную разметку/плавность. Она не назначает
такие грани внешними молча и не разрешает автоматическую доводку.
Для междустанционного U автоматическое изменение соответствующего корпуса
по-прежнему запрещено; нативная диагностика такого диапазона поддерживается.

Завершённое сопоставление не гарантирует, что любой требуемый зазор достижим
в данном бюджете. В испытании MQ-20 с порогом 0,025 ft и бюджетом 0,05 ft
итоговая уточнённая проверка не прошла; результат не был разрешён к применению.
Это штатный отказ ограничения, а не повод отключать проверку.

4. ГРАНИЦЫ ИСПЫТАНИЙ

Нативные испытания выполнены под Linux с OpenVSP 3.51.0 и Python 3.12.
Проверены CH1, MQ-20, MQ-28 и Spirit Mosquito, обрезка, повороты и негативные
сценарии. В браузере проверены открытие без изменения VSP3, крупные копии,
принудительное завершение сервера, новый порт, резерв настроек и повреждённый
последний снимок. Точные результаты находятся в Validation.json.

Нативный Windows-запуск и выполнение BAT в cmd.exe в этой среде не проводились.
Проверка на целевом Windows-компьютере начинается с Check_Setup.bat;
при ошибке нужны Setup_check.json, launch.log и текст окна запуска.

Неизменённые контрольные модели лежат в Prepared_models. Они не получают
новый сертификат расчёта от включения в архив. Прежние ограничения по точности
TRI, конечным выборкам, физической площади и применимости решателей сохранены.
